# 🤖 J.A.R.V.I.S. — Just A Rather Very Intelligent System

**Версия:** 0.7.0  
**Статус:** Активная разработка  
**Python:** 3.13+  
**LLM:** Google Gemini 3.1 Flash Lite (внутренний) + Flash Live Preview (внешний)  
**Embeddings:** Gemini Embedding 2 (768-dim)  
**База данных:** PostgreSQL 16+ с расширением pgvector  
**Агент памяти:** Gemini 3.1 Flash Lite (отдельный экземпляр)  
**Orchestration:** LangGraph StateGraph  
**RAG:** Векторный поиск по долговременной памяти

**Агент Памяти (MemoryAgent)** — автономный модуль, запускающийся:
- Автоматически через 2 минуты бездействия
- По команде пользователя (`force_memory_consolidation`)
- Анализирует необработанные факты из `session_log` и распределяет их по уровням памяти

**Граф Обработки (TaskGraph)** — построенный с помощью LangGraph StateGraph:
- agent — вызов LLM для анализа запроса
- tools — выполнение запрошенных инструментов
- emergency_stop — аварийная остановка при превышении лимита шагов (8)
- Условные переходы определяют поток выполнения на основе наличия tool_calls

## 🧠 Система долговременной памяти

JARVIS использует **трёхуровневую архитектуру памяти**, основанную на принципах когнитивного моделирования:

### 🌡️ Терминология уровней памяти

| Уровень | Название | Характеристики | Использование |
|---------|----------|----------------|---------------|
| **Горячая память** | `UserProfile` | Постоянное хранение критически важных фактов | Актуальные данные, которые нужно помнить всегда (ID, настройки, проекты) |
| **Теплая память** | `VectorMemory` | Семантический поиск через pgvector (768-dim) | Контекстные знания, технические детали, проектные решения |
| **Холодная память** | `SessionLog` | Неизменяемый лог всех сообщений | Контекст текущей сессии, аудит диалога |

### 📊 Структура базы данных

```
┌─────────────────────────────────────────────────────────────┐
│                    PostgreSQL Database                       │
│                     jarvis_memory                            │
└─────────────────────────────────────────────────────────────┘
                              │
        ┌─────────────────────┼─────────────────────┐
        ▼                     ▼                     ▼
┌────────────────┐  ┌─────────────────┐  ┌────────────────┐
│  user_profile  │  │  vector_memory  │  │   session_log  │
├────────────────┤  ├─────────────────┤  ├────────────────┤
│ id             │  │ id              │  │ id             │
│ key (unique)   │  │ text            │  │ session_id     │
│ value (text)   │  │ embedding (vec) │  │ role           │
└────────────────┘  │ meta_data (json)│  │ content        │
                    └─────────────────┘  │ timestamp      │
                                         └────────────────┘
```

### 🔍 Принцип работы

1. **Горячая память** (`UserProfile`)
   - Ключ-значение пары для фиксированных фактов
   - Примеры: "Пользователь разрабатывает проект ESTO на Python", "День рождения 2 мая"
   - Мгновенный доступ без векторного поиска

2. **Теплая память** (`VectorMemory`)
   - Векторизация текста (768-мерные эмбеддинги)
   - Косинусное сходство для семантического поиска
   - Примеры: технические решения, детали проектов, важные факты из бесед

3. **Холодная память** (`SessionLog`)
   - Лог всех реплик с метками role (user/assistant/fact)
   - Временные метки для отслеживания контекста
   - Используется для построения контекста текущей сессии

### `settings.py` — Настройки

**Архитектура промптов (трёхуровневая система агентов):**

1. **Supervisor Core** (`supervisor_prompt`)
   - Координатор ИИ-системы, делегирует задачи между специалистами
   - Специалисты в подчинении:
     - CalendarAgent — Эксперт по тайм-менеджменту
     - ResearchAgent — Аналитик-исследователь
   - Строгое делегирование без собственных инструментов
   - Формат вывода: направление + поставленная задача

2. **CalendarAgent** (`calendar_agent_prompt`)
   - Аналитик планирования и расписания
   - Работает в бэк-офисе, готовит точные календарные решения
   - Chain of Thought:
     1. Вычисление целевых дат
     2. Проверка загруженности через `calendar_get_schedule_tool`
     3. Анализ свободных окон
     4. Формирование черновика плана
     5. Вызов `request_user_approval_tool` для согласования
   - Обработка апрувов: ОДОБРЕНО / ОТКЛОНЕНО / ПРАВКИ

3. **ResearchAgent** (`research_agent_prompt`)
   - Аналитик-исследователь, собирает факты
   - Проверка погоды, поиск рецептов, сбор информации
   - Режим тестирования (оффлайн): имитация внешнего поиска
   - Приоритет использования данных из истории диалога

**Голосовой фронтенд (Gemini 3.1 Flash Live Preview):**
- **Модель:** `gemini-3.1-flash-live-preview`
- **Промпт:** Инструкция для голосового интерфейса с маршрутизацией
- **Режим маршрутизации:**
  - "запиши", "спланируй", "когда", "что у меня", "погода", "найди" → `delegate_heavy_task`
  - После апрува → повторный вызов `delegate_heavy_task` с `approval_status`
- **Инструменты:** `delegate_heavy_task`, `memorize_important_fact`, `force_memory_consolidation`

**Агент Памяти** (`MEMORY_AGENT_PROMPT`):
- Автономный технический модуль анализа сырых фактов
- Критическое правило времени: перенос относительных указаний в абсолютный формат
- Формат вывода: JSON с hot_updates, hot_deletes, warm_additions
- Жёсткий фильтр мусора: игнорирование системных и технических команд

**Внутренний агент (Gemini 3.1 Flash Lite):**
- **Модель:** `gemini-3.1-flash-lite`
- **Промпт:** Системный инструктаж агента (бэк-офис, точность, без вежливости)

**Голосовой фронтенд (Gemini 3.1 Flash Live Preview):**
- **Модель:** `gemini-3.1-flash-live-preview`
- **Промпт:** Инструкция для голосового интерфейса с делегированием
- **Инструменты:** `delegate_heavy_task`, `memorize_important_fact`, `force_memory_consolidation`

**База данных:**
- **СУБД:** PostgreSQL 16+ с расширением pgvector
- **Таблицы:** `user_profile`, `vector_memory`, `session_log`
- **Переменные окружения:** `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT`, `DB_NAME`

**Пути:** `token.json`, `credentials.json` для Google API

## 📋 Реализованный функционал

### 1. **Калибровка и сборка**
- `bootstrap.py` — фабричная функция для сборки приложения
- Автоматическое внедрение зависимостей между модулями
- Подключение Live API сервиса, внутреннего агента, агента памяти и репозитория
- Инициализация базы данных с расширением pgvector
- Создание `MemoryLLMService` для автономного анализа фактов

### 2. **Ввод/Вывод (UI + Обработка команд)**

**Терминальный интерфейс:**
- ASCII-анимация (вращающийся тор) с 3D-проекцией
- Многопоточная отрисовка (~30 FPS) с параллельной обработкой ввода
- Визуальная зона чата с прокруткой истории сообщений
- Строка статуса и активный ввод пользователя
- Поддержка ввода через клавиатуру (backspace, enter, символы)

**Аудио:**
- Запись аудио с микрофона (16kHz, PCM)
- Воспроизведение аудио (24kHz, PCM)
- Очередь аудио-чанков для плавного воспроизведения

### 3. **Искусственный интеллект**

**Трёхуровневая система агентов:**
- **Supervisor Core** — делегирует задачи между специалистами
- **CalendarAgent** — планирование и расписание
- **ResearchAgent** — поиск информации и проверка погоды

**Голосовой фронтенд (Gemini 3.1 Flash Live Preview):**
- Real-time голосовой диалог
- Автоматическое распознавание речи (STT)
- Автоматический синтез речи (TTS)
- Инструменты делегирования и запоминания для передачи задач и сохранения фактов

### 4. **Долговременная память**

**Агент Памяти (`MemoryAgent`):**
- Автономный модуль анализа сырых фактов из `session_log`
- Запускается через `consolidate()` — анализирует и распределяет факты по уровням памяти
- Использует отдельный экземпляр Gemini 3.1 Flash Lite (через `MemoryLLMService`)
- Логирует результаты в `logs/memory_agent.log`

**Репозиторий памяти (`PostgresRepository`):**
- `append_session_log()` — сохранение реплики диалога в холодную память
- `get_session_logs()` — получение истории текущей сессии для контекста
- `update_user_profile()` — обновление факта в горячей памяти
- `get_user_profile()` — получение всех известных фактов
- `add_vector_memory()` — сохранение факта с эмбеддингом в теплую память
- `search_vector_memory()` — семантический поиск по векторам (cosine distance)
- `get_unprocessed_facts()` — выборка необработанных фактов для агента
- `mark_facts_as_processed()` — пометка фактов как обработанных
- `delete_user_profile_key()` — удаление ключа из горячей памяти

**Модели данных:**
- `UserProfile` — ключ-значение для критически важных фактов
- `VectorMemory` — текст с 768-мерными эмбеддингами и метаданными
- `SessionLog` — лог сообщений с полем `processed` (bool) для отслеживания агентом

**Расширение pgvector:**
- Асинхронное создание расширения при инициализации БД
- Векторное сходство через косинусное расстояние
- Индексация для быстрого поиска по векторам

**Автоматическая консолидация:**
- Движок запускает агента через 2 минуты бездействия
- Пользователь может вызвать принудительную консолидацию через `force_memory_consolidation`

### 5. **Инструменты (Tools)**

| Инструмент | Описание |
|-----------|----------|
| `TimeTool` | Текущая дата/время (русифицированные названия месяцев и дней) |
| `CalendarAddEventTool` | Создание событий в Google Calendar (обычные и all-day) |
| `CalendarAddTaskTool` | Создание To-Do задач в Google Tasks |
| `CalendarGetScheduleTool` | Просмотр расписания по календарям и задачам |
| `DelegateHeavyTaskTool` | Делегирование сложных задач внутреннему агенту |
| `MemorizeFactTool` | Сохранение важных фактов в холодную память (SessionLog) |
| `ForceConsolidationTool` | Принудительный запуск агента памяти |
| `SearchMemoryTool` | RAG-поиск по долговременной памяти (взаимодействие с `search_user_memory`) |
| `RequestUserApprovalTool` | 🆕 Согласование сложных расписаний и планов (черновики событий и задач) |

### 6. **Google Calendar Integration**
- Аутентификация через OAuth2 (автоматическое обновление токенов)
- 7 календарей: университет, учеба дома, работа, привычки, спорт, встречи, быт
- Поддержка событий и задач с фильтрацией по времени

### 7. **LangGraph StateGraph**
- Граф обработки с узлами: `agent`, `tools`, `emergency_stop`
- Условные переходы на основе наличия `tool_calls`
- Жесткий лимит шагов (8 итераций) для предотвращения зацикливания
- Автоматическая маршрутизация между LLM и инструментами

### 8. **Динамическая генерация промптов**
- Движок компилирует системный промпт с учетом горячей памяти
- Актуальные факты подставляются в промпт перед каждым запросом
- Гарантирует, что голосовой интерфейс всегда имеет актуальный контекст

## 🚀 Запуск

### Windows
```bash
run.bat
# или
uv run src/main.py
```

### Предварительные требования

1. **PostgreSQL 16+** с расширением `pgvector`
2. **Создание базы данных:**
   ```sql
   CREATE DATABASE jarvis_memory;
   CREATE EXTENSION vector;
   ```
3. **Переменные окружения в `.env`:**
   ```env
   GEMINI_API_KEY=your_api_key
   DB_USER=postgres
   DB_PASSWORD=jarvis_pass
   DB_HOST=localhost
   DB_PORT=5432
   DB_NAME=jarvis_memory
   ```
4. **Docker (альтернативный способ):**
   ```bash
   cd src
   docker-compose up -d
   ```
   - Образ: `pgvector/pgvector:pg16`
   - Контейнер: `jarvis_postgres`
   - Порт: `5432`

### Базовая архитектура памяти

**Автоматическая консолидация:**
- Движок (`JarvisEngine`) запускает агента памяти через 2 минуты бездействия пользователя
- Пользователь может вызвать принудительную консолидацию через инструмент `force_memory_consolidation`
- Агент анализирует необработанные факты из `session_log` и распределяет их по уровням памяти

**Поток сохранения данных:**
1. **Горячая память** — через `memorize_important_fact` инструмент
   - Вызывается голосовым агентом при получении важных фактов
   - Сохраняется в таблицу `user_profile` (ключ-значение)
   
2. **Холодная память** — автоматически через движок
   - Каждое сообщение (user/assistant) сохраняется в `session_log`
   - Используется для построения контекста текущей сессии
   - Поля `processed` (bool) отслеживает статус обработки агентом

3. **Теплая память** — через консолидацию агентом
   - Агент памяти анализирует сырые факты из `session_log`
   - Векторизирует важные факты и сохраняет в `vector_memory`

## 📝 Примечания
